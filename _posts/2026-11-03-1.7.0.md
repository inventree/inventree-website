InvenTree 1.7.0 has been released! This release includes a critical security fix, a number of new features, improvements, and bug fixes. We recommend all users to update to this version as soon as possible.

### Changelog

Major changes are documented in the `CHANGELOG.md` file in the repository. For a full list of changes, please refer to the [release notes](https://github.com/inventree/InvenTree/releases/tag/1.7.0).

### Update Procedure

To update to the latest version of InvenTree, please follow the updating instructions provided in the [InvenTree documentation](https://docs.inventree.org). Note that the particular update procedure may vary depending on your installation method.

## Security Fixes

**This release contains a fix for a critical, low-complexity privilege escalation vulnerability, affecting a range of releases since 2025.** Full details, including the associated security advisory, will be published shortly after release — please see our [earlier announcement](/blog/2026/11/03/security-release) and watch our [security advisories page](https://github.com/inventree/InvenTree/security/advisories?state=published) for the disclosure. If you have not already done so, please update to 1.7.0 as a priority.

> Advisory: *to be added once published*

A number of other security vulnerabilities and hardening improvements are also included in this release.

### CSV Export Formula Injection

[PR #13084](https://github.com/inventree/InvenTree/pull/13084) sanitizes user-controlled data before it is written into exported CSV files, preventing [CSV injection](https://owasp.org/www-community/attacks/CSV_Injection) attacks where a crafted cell value could execute a formula when the export is opened in a spreadsheet application. [PR #13110](https://github.com/inventree/InvenTree/pull/13110) is a follow-up fix which relaxes this escaping for legitimate numeric values.

### Report Data Hardening

[PR #13111](https://github.com/inventree/InvenTree/pull/13111) hardens data access during report generation, excluding sensitive data from the report rendering context and preventing database writes from being triggered as a side effect of generating a report or label.

### Session & Token Hardening

Several related fixes tighten up session and API token handling in this release:

- Revoking an already-revoked token no longer overwrites the original revocation details ([PR #13149](https://github.com/inventree/InvenTree/pull/13149))
- Token validity checks now also confirm that the owning user account is still active ([PR #13148](https://github.com/inventree/InvenTree/pull/13148))
- Tokens are now masked more securely when displayed, with a fixed lowercase-handling bug and more consistent expiry date checking ([PR #13155](https://github.com/inventree/InvenTree/pull/13155))
- Deleting a `UserSession` via the Django admin interface now also logs out the associated user, rather than leaving the session active ([PR #13145](https://github.com/inventree/InvenTree/pull/13145))

### Additional Hardening

This release also includes routine security-related dependency updates, including CA certificate updates ([PR #13057](https://github.com/inventree/InvenTree/pull/13057)) and a batch of Python dependency security patches ([PR #13108](https://github.com/inventree/InvenTree/pull/13108)).

## Breaking Changes

While we strive to maintain backward compatibility, there are some breaking changes in this release. While many of these are minor, and should not affect most users, we recommend that you review the list of breaking changes to ensure that your installation will continue to function as expected after the update. Each breaking change is documented in detail at the links below:

### Pricing Model Refactor

[PR #13034](https://github.com/inventree/InvenTree/pull/13034) moves pricing functionality into a new, dedicated `pricing` app, with its own API endpoints and a new "pricing" permission role. Existing users with `part` role permissions automatically retain pricing access via a data migration, laying the groundwork for further pricing improvements in future releases.

### Stock Tracking Replaced by Audit Log

[PR #13101](https://github.com/inventree/InvenTree/pull/13101) removes the legacy "stock item tracking" model and its associated API endpoints, migrating existing entries into the new global audit log introduced in this same release (see "Changelog / Edit History" under New Features, below). The old stock tracking table only ever captured a subset of model changes; the audit log provides a more complete and consistent record. Any external client applications which read stock tracking data via the old API will need to be updated to use the new `/api/audit/` endpoints.

## New Features

### Changelog / Edit History

[PR #13069](https://github.com/inventree/InvenTree/pull/13069) introduces a global audit log, built on [django-auditlog](https://django-auditlog.readthedocs.io/en/latest/), which tracks changes made to internal data throughout the system. The log is exposed via new read-only `/api/audit/` endpoints, and replaces the previous, more limited stock tracking table (see Breaking Changes, above).

### Token Issuance Notifications

[PR #13141](https://github.com/inventree/InvenTree/pull/13141) notifies a user whenever a new API token is issued against their account — whether via the API, the UI, or by an administrator — and separately warns administrators if no email backend is configured, meaning such security alerts cannot be delivered.

### Plugin-Launched Forms & Action Context

[PR #13174](https://github.com/inventree/InvenTree/pull/13174) allows plugins to dynamically launch native modal forms without needing to supply their own React components — for example, triggering a built-in API form from a custom primary action. [PR #13172](https://github.com/inventree/InvenTree/pull/13172) complements this by passing the current page's target model and instance ID through to plugin-registered primary actions, giving plugins more context about where they were triggered from.

### Stock Adjustment Barcode Actions

[PR #13170](https://github.com/inventree/InvenTree/pull/13170) implements a number of previously-stubbed stock adjustment actions for barcode scanning, rounding out barcode-driven workflows for adjusting stock.

### Default Stock Location from Part

[PR #12916](https://github.com/inventree/InvenTree/pull/12916) automatically selects the default stock location for a new stock item, if one has been configured against the part being stocked.

### Instance Identity Proof for Federation

[PR #13030](https://github.com/inventree/InvenTree/pull/13030) adds an optional mechanism for an InvenTree instance to cryptographically prove its identity to a federation participant, without exposing its instance ID directly. A time-limited, replayable proof is computed using HKDF and HMAC, and can be requested as an optional parameter on the root API response — early groundwork for future [federation](https://github.com/inventree/InvenTree/issues/4562) work.

### Badge Tooltips

[PR #13074](https://github.com/inventree/InvenTree/pull/13074) adds explanatory tooltips to the status badges shown on detail pages, making it clearer at a glance what each badge represents.
